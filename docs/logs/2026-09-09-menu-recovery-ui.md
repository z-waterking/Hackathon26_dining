# 2026-09-09 六周菜单生成恢复入口

- 六周菜单页新增“恢复生成记录”，按需通过统一 `diningApi` 查询生成记录，不在页面初始化时额外取数。显示已完成周次、阶段和安全的失败定位，不显示内部 Prompt、模型原始输出或重试明细。
- 生成失败保留已有草案和运行 ID，并在后台刷新恢复记录；不会自动重跑六周、填入示例菜单或隐式降级成本地生成。
- 可恢复失败记录提供“继续生成剩余周次”，只提交原运行 ID。关闭记录对话框后复用菜单页内等待，允许继续导航和操作其他页面，防止本页重复生成、重复恢复或冲突保存。
- 完成但尚未手工保存的结果可通过“查看已生成菜单”取回，无需再次调用 GPT；即使 AI 服务配置暂时不可用，已完成结果仍可读取。所有恢复结果仍需人工审核与点击保存。
- HTTP 错误统一保留 `runId/code/week/stall/day/meal/slot` 白名单诊断；不会把任意错误对象、内部系统指令或原始生成内容暴露给页面。
- 新增隔离测试：失败后从第 3 周继续、恢复期间局部等待与其他页可操作、防重复、已完成结果只读取不重生成、恢复检验失败保留旧草案及运行 ID。所有浏览器业务请求均拦截，不访问真实业务库或模型。
- 验证：API 客户端 6 项测试通过；直接生成与恢复页面 14 项桌面/手机 E2E 通过；构建成功。恢复记录桌面/手机截图以 1280×426、约 34 KB JPEG 接触表核对，无布局溢出。全仓最终验证由主任务汇总。
