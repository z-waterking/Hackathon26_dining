# 2026-09-09 逐周生成与即时展示

## 行为变化

- 一次点击自动顺序生成第 1–6 周。第 1 周校验通过并存为 checkpoint 后立即推送具体菜单，页面即可查看；第 2 周输入包括第 1 周，第 3 周输入包括第 1、2 周，以此类推。保持完整有效菜库和当前规则/已批准 Action，不修改部署、Prompt 或业务资料。
- 六格进度显示“已展示 / 生成中 / 等待中”；只有已生成周次有菜单，不预先把未来周次画为空菜单。可以查看餐次/档口并切换其他页面，生成继续。
- 已有完整草案与本次逐周预览分开保存为页面状态。预览只读，六周及独立检验完成后才开放编辑、保存和完整导出；不自动保存、不自动批准。中途失败保留前面周次，可继续恢复。

## 实现与保护

- 后端 `runMenuWorkflow/resumeMenuWorkflow` 新增业务进度回调，依次发送 `started/week/inspecting`。回调只发布服务端校验且已落库的实体菜品，下一周仍使用全部历史成功菜单的紧凑结构；回调输出为复制数据，不能反向修改生成上下文。
- 新增 `/api/plans/generate-stream`、`/api/plans/resume-stream` NDJSON 流。15 秒保活，事件写出后让出执行权，下一周请求之前即可刷到客户端。与旧生成/恢复/检验共用工作流锁；旧 JSON 接口兼容保留。
- 流通过公开字段过滤，错误只含安全消息和运行/周次定位。断开只分离页面，后台继续保存；慢客户端背压最多等 30 秒，不允许慢流永久卡住后续周次或独占业务锁。
- API 层处理 UTF-8 跨块、半行、多行、流中错误、断开和缺少完成事件，不把 HTTP 200 或已生成 6 周当作检验完成，不自动重试付费请求。
- 服务端拒绝 `partial` 预览；即使移除标志，`gpt-direct` 菜单仍需可信的完整检验记录，不能把第 6 周刚完成的预览当作最终草案。
- 使用 OpenAI Docs 技能核对 [Responses 上下文管理](https://developers.openai.com/api/docs/guides/conversation-state)，保留显式传入已生成菜单的业务上下文方案，不切换模型、不改为服务端持久会话或只依赖历史摘要。
