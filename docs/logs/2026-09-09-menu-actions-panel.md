# 2026-09-09 · 六周菜单常驻排菜 Action 面板

## 请求与改动

进入六周菜单时有固定区域展示排菜Action，避免只在菜单生成后才看到要求或将“批准事项”误解为“批准排菜要求”。

- 新增 `MenuActionsPanel.jsx` 与响应式样式，在菜单标题下、生成控件前常驻；使用页面布局中的卡片窗口，不使用遮挡其他页面的弹窗或悬浮层。
- 显示当前可用排菜要求、批准总数、待审批排菜事项、服务及其他非排菜改善。每个排菜事项展示目标档口、具体要求、状态及不参与原因，可跳转独立Action模块管理。
- 复用现有 `diningApi.workspace.load()` 的 `data.actions`，审批后经原共享reload更新，无直接取库、额外自动AI调用或审批变更。
- `shared/menu-action-state.mjs` 统一前后端“正式/反馈关联/已批准/启用/要求非空”判定，保留原模拟数据隔离与历史生成兼容；待审批等事项仅说明，不进入模型要求。
- `MenuWorkflow.jsx` 空快照文案改为“此菜单生成时未纳入排菜Action”，当前面板用于下一次生成，不能据此声称旧菜单已落实。
- README与CHANGELOG记录使用方式；未提交或推送，保留既有未提交内容，不修改正式业务数据或模型配置。
