# 2026-09-09 原菜单一次性入库

## 本次目标与实现

用户澄清要求现在直接完成原Excel处理和入库，后续菜品从库获取。因此撤销上一版在启动/生成/恢复/复检时读取原菜单的方式；并非只补一个临时缓存。

- 新增 `stall-catalog-import.mjs`：按档口、规范化菜名、数值价格、结构化单位定位现有记录，复用ID，只追加缺少的源证据。保留人工标签、英文、分类、停用状态、热量、过敏原及其他既有字段；新记录仅取真实来源，食品标签仍未知。
- 新增 `tools/Import-StallCatalog.mjs`：默认只读preview，显式`--apply`先一致性备份，再通过Repository单事务写入菜品/来源映射/审计。重复运行幂等，稳定新ID含单位，冲突拒绝覆盖。运行中菜单禁止换库。
- `dishes`存具体菜品，`meta.preprocessed-stall-catalog`存12档源映射、原表SHA256、单元格、去重/异常及导入版本。新标记`storageMode=database`、`importVersion=stall-import-v1`。
- `stored-stall-catalog.mjs`不含文件I/O：由DB来源关联和当前菜品active/标签生成候选投影。已停用菜不会重新启用，重新启用后立即入池；源表外补充档口从DB独立读取。
- index/app/workflow不再调用原菜单解析，也删除生成/读取/恢复期间的原菜单文件存在或哈希检查。搬走/修改原Excel不影响已入库菜品。菜库变化仍由DB快照识别，不允许混用旧运行。
- `餐厅排菜规则+示例.xlsx`作为独立规则来源仍保留既有同步，这次仅取消指定原菜单Excel的运行依赖。
- POS单位及销量筛选支持“位”，不把位换成份；同名不同单位仍独立匹配和统计。启动脚本仅新建数据库时导入一次，已有库不因缺解析文件而重新解析原菜单。
- 使用Spreadsheets技能按只读方式核对源表与控制数，不修改或导出原Excel。

## 经用户确认停止的运行

检测到用户此前启动的真实六周菜单仍在运行，先询问以避免换库使已付费生成失效。用户明确选择“停止当前生成并导入”后，停止服务并将`MR-461688c7-134b-4d57-a2ad-44b94dad90bd`标为cancelled，保留已完成第1周及共18个成功档口输出（第2周寻味已完成）。原运行和业务菜单不删除、不伪造完成。

停止前备份：`app/data/backups/dining-before-user-cancel-import-2026-09-09T08-38-25-757Z.sqlite`。当时等待中的第2周五味请求用量标记为取消/上游结果未知；进程停止不能保证上游未收费，不假记为0费用。不自动恢复或重新发起付费生成。菜库切换后若重新排菜，应新建运行。
